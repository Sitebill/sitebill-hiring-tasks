что осталось и почему. Это нормальный результат.

## Что здесь есть

Урезанная копия паттерна изоляции тенантов нашей SaaS-платформы:

- `Tenant` определяется по заголовку `X-Tenant` (slug), middleware `ResolveTenant`;
- модели тенанта используют трейт `BelongsToTenant` (глобальный скоуп по `tenant_id`);
- пример готовой сущности `Property` с контроллером и тестами `tests/Feature/PropertyIsolationTest.php`;
- Gate `manage-tenant`: администратор своего тенанта.

## Запуск

```bash
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate
vendor/bin/pest
```

Тесты работают на SQLite в памяти, отдельная БД не нужна. Нужен PHP 8.4.

## Что нужно сделать

Добавьте сущность **«Заявка на показ»** (`App\Models\ViewingRequest`):

| Поле | Правила |
|---|---|
| `tenant_id` | проставляется автоматически |
| `property_id` | объект **того же тенанта**, обязателен |
| `name` | строка до 100 символов, обязательна |
| `phone` | корректный телефон, обязателен |
| `visit_at` | дата и время визита, обязательна, только в будущем |
| `status` | `new` (по умолчанию), `confirmed`, `cancelled` |

### API (маршруты в `routes/api.php`)

- `POST /api/viewing-requests` — создать заявку. Доступно **любому посетителю, включая
  неавторизованного**. Ответ `201`, в теле `id`, `status`.
- `GET /api/viewing-requests` — список заявок текущего тенанта. Только администратору
  **этого** тенанта (`Gate::allows('manage-tenant')`). Неавторизованный получает `401`,
  не администратор `403`. Ответ — JSON-массив объектов с полями `id`, `property_id`, `name`,
  `phone`, `visit_at`, `status`.

### Консольная команда

`php artisan viewing-requests:purge-old {tenant}` — удаляет заявки указанного тенанта
(аргумент — slug), у которых `visit_at` старше 30 дней. Заявки других тенантов не трогает.
Выводит число удалённых заявок.
